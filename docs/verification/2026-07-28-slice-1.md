## How to re-run it

```
cp hub.config.example.json hub.config.json
npm install
node scripts/serve.mjs dev
# then, in another shell
curl -s http://127.0.0.1:2886/ | head -c 2000
curl -s "http://127.0.0.1:2886/api/ledger/stream?once=1"
```

The browser half used a throwaway Playwright script (not committed: this repo
has no test framework by design). It navigated to the hub, waited for
hydration, read the DOM, inserted a ledger row directly into SQLite while the
page stayed open, and re-read the DOM without reloading.

## Walked, and what was seen

**1. It starts.** `node scripts/serve.mjs dev` printed:

```
[hub] dev on http://127.0.0.1:2886
[hub] Local only: nothing else on your network can reach this.
```

Host and port both came from config. Ready in 185ms.

**2. The database was created and migrated on first request.** `data/hub.db`
plus `-wal` and `-shm` appeared (WAL confirmed). `PRAGMA user_version` returned
`1`, meaning migration 0 applied exactly once. The `action_ledger` schema
matched the intended v1 column set including the columns no slice uses yet
(`job`, `pid`, `transcript`, `route`, `started_at`) and the full state enum, so
no rebuild-and-copy is owed later.

**3. TODAY rendered, with honest empty states.** Server HTML and the hydrated
DOM agreed:

- Logo: `ATTENTION HUB`
- Nav: `TODAY` active, `BOARD` / `SESSIONS` / `JOBS` greyed and marked
  "Not built yet." This matches the approved mock's embedded hub screenshot
  (nav order, waiting-for-you at the top, counts on the right).
- Counts: `0 running / 0 queued`
- Cards, in order: "Waiting for you", "Jobs", "Not set up yet"
- Copy: "Nothing needs you right now...", "No jobs yet...", "No AI tool is
  configured yet..."
- Version line: "Attention Hub v0.1.0. Running on this machine only. No
  telemetry..."
- No sample rows anywhere. Nothing invented.

**4. It actually hydrated.** React fiber keys were present on the `.app` root
(2 keys). This is checked explicitly rather than assumed, because the specific
failure this catches (chunks load, React boots, no fiber attaches, every click
dead) renders a page that LOOKS correct.

**5. The live stream works, with no reload.** With the page open:

- Inserted one `running` row directly into SQLite.
- Within 4 seconds the topbar read `1 running / 0 queued` and the jobs strip
  showed `live-check: stream running`. No reload, no user action.
- Deleted the row; within 4 seconds the topbar was back to `0 running / 0
  queued` and the empty state returned.

**6. The poll-fallback contract holds.** `GET /api/ledger/stream?once=1`
returned `200` with keys `counts`, `jobs`, `attention`, byte-identical in shape
to the streamed payload. Confirmed from inside the page, so it is the same path
the fallback would take.

**7. The diff suppression works.** A 5-second raw `curl -N` against the stream
received exactly ONE frame and then silence, which is correct: the snapshot did
not change, and the forced keepalive emit is every 16 ticks (about 24s).

**8. The wire payload is trimmed.** The streamed job objects carried no `actor`,
no `job` spec, and no `pid`. That is `toView()` doing its job, and it is a
security property rather than tidiness.

**9. ZERO external network requests.** The browser's full request list for the
whole session contained nothing outside `http://127.0.0.1:2886`. This is the
mechanical proof behind the no-telemetry claim, and it is the single most
important line in this document.

**10. Zero console errors and zero page errors** across load, live update, and
teardown.

**11. Typecheck, build, and the config-first check are green.**

- `npx tsc --noEmit`: clean.
- `npm run build`: compiled, no warnings, three routes (`/`, `/_not-found`,
  `/api/ledger/stream`), all dynamic as intended.
- `node scripts/check-paths.mjs`: clean, 19 files, no absolute paths, no
  hardcoded ports.

## Found and fixed during the walk

**Turbopack traced the whole project.** The build warned "Encountered unexpected
file in NFT list" because `readFileSync(path.join(process.cwd(), ...))` in the
config loader looks like a dynamic dependency. Fixed with the exact marker
`path.join(/*turbopackIgnore: true*/ process.cwd(), x)` in `src/lib/config.ts`,
`src/lib/version.ts` and `next.config.ts`. The spacing inside that comment
matters; a spaced variant did not suppress it. Build is now warning free.

**The no-telemetry gate blocked the repo's own poll fallback.** Gate testing
(below) caught that `src/components/useEventStream.ts` was rejected: the
`hub-allow-network:` marker was on the comment line ABOVE the `fetch`, and the
gate reads one line at a time. Marker moved onto the fetch line. Worth noting
that this is a gate doing its job, and it is exactly the kind of thing that
would otherwise have been discovered by whoever tried to make the first commit.

**An open EventSource means `networkidle` never fires.** The first walk attempt
timed out after 30s waiting for network idle on a page that, by design, holds a
stream open forever. Any future browser automation against a hub page must wait
for `domcontentloaded` plus a hydration beat instead. Recorded in
`docs/claude/architecture.md` so it is not rediscovered.

## The gates were tested, not assumed

Installed with `bash .githooks/install.sh`, then each gate was proved by staging
a violation and attempting a real commit. Every attempt was rejected and HEAD
never moved.

| Gate | Test | Result |
|---|---|---|
| Em dash | staged a line with U+2014 | BLOCKED, named the file and line |
| Denylisted term | staged a real home path | BLOCKED |
| No telemetry | staged `fetch(...)` under `src/` | BLOCKED |
| Config first | staged an absolute path under `src/` | BLOCKED |
| Fail closed | moved `denylist.local` aside | commit REFUSED (exit 1), audit REFUSED (exit 2) |
| Real tree | staged the whole slice | PASSED, so the gates are not blocking legitimate work |

The fail-closed test is the one people skip and the one that matters: a scanner
that greens on a missing list manufactures confidence.

Whole-tree `bash .githooks/release-check.sh` is clean over ALL 43 tracked files,
including the README, the LICENSE, ADR-0001 and the 60KB mock that landed
BEFORE any gate existed. `--generic-only` (the CI shape) also runs clean and
says out loud that the denylist half was skipped, rather than reporting a check
it did not perform.

## What could NOT be walked, and why

**The Chrome extension was not connected**, so this walk used headless Chromium
instead of the browser instrument the house rule names. Everything above is a
real browser with real hydration and a real EventSource, so the coverage is
equivalent for what slice 1 ships. What headless does NOT cover: how it looks on
Andrew's actual display, and OS-level notification behaviour. **Neither of those
is in slice 1** (notifications are a later slice), so nothing shipped here is
resting on an unverified claim. Re-walk in Chrome before anything is handed to a
real user.

**`runThroughLedger()` is typechecked but not yet exercised.** Nothing in slice
1 mutates anything, so there is no caller. The schema it writes against was
verified directly (see item 2), and its first real exercise belongs to the slice
that adds the first verb. Recorded here rather than quietly implied.

**Windows was not walked.** The Windows-specific work in this slice (CRLF
pinning in `.gitattributes`, `start.cmd`, spawning `process.execPath` against
Next's JS entry instead of the `.bin` shim, a cross-platform `build:check`
instead of an inline env assignment) is built to spec and reasoned about, but
this machine is macOS. First Windows run is a real test, not a formality.

**Production mode (`start.sh start`) was not walked**, only `npm run build` and
dev mode. Low risk, but not verified. (Walked in the second pass, where it also
became the default.)

**Reaching the hub through a non-loopback hostname was not walked.** That path
is where `allowedDevOrigins` matters, and loopback never reproduces its failure
mode. It becomes testable when the setup page exists.
